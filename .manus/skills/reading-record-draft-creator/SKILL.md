# 読書記録 PR作成スキル (Reading Record Draft Creator)

ユーザーが提供する断片的なメモから「3Cフレームワーク」に基づいた読書記録のドラフトを作成し、週末に実践（Compile）するためのタスクリストを含めた Pull Request を作成します。

## Key Parameters / Rules (制約事項)

- 作業ディレクトリ: content/entries/
- ファイル形式: Markdown (.md または .mdx)
- ユーザーの執筆体験（Obsidianの利用）を阻害しないため、複雑な装飾は避け、シンプルなMarkdownで記述してください。
- 出力ファイルは必ず published: false を設定してください。

## Common Workflows (実行ステップ)

### Step 1: 情報の構造化 (Compress)

ユーザーから渡された入力データを分析し、以下の要素を抽出・補完してください。

- 書籍情報: タイトル、著者（不明な場合は検索して補完）
- 学びの要点 (20%の抽出): 最も重要な概念を1〜3つに絞り、チャンク化（短い要約や比喩）してまとめる。
- 業務への接続アイデア: ユーザーのメモを基に、フロントエンド開発やB2B SaaSの要件など、実際の業務にどう応用できるかの仮説を立てる。

### Step 2: ファイルの生成

content/entries/ 配下に [英数字のslug].md というファイル名で作成してください。
ファイルの先頭には以下のメタデータ（Frontmatter）をYAML形式で付与してください。
（注意: 実際にファイルに書き込む際は、行頭と行末をハイフン3つ --- で囲んでください）

title: "[メモから推測した記事タイトル]"
book_title: "[書籍のタイトル]"
author: "[著者名]"
date: YYYY-MM-DD
published: false

本文は以下の見出し構成としてください。

```md
## 読むきっかけ

（ユーザーの入力から推測して簡潔に記載）

## 学びの要点

（Step 1で構造化した内容を記載）

## 業務への接続アイデア

（Step 1で仮説立てた応用アイデアを記載）
```

### Step 3: Git操作とPR作成

1. main ブランチから最新の状態を取得し、 draft/YYYYMMDD-[slug] という新しいブランチを作成する。
2. 作成したファイルをコミットし、リモートにプッシュする。
3. main ブランチに対して Pull Request を作成する。

### Step 4: PR概要欄の作成 (Compileの準備)

Pull Request の Description (本文) には、ユーザーが週末に90分以内で実行すべき「実践・検証タスク」をチェックリスト形式で必ず出力してください。
タスクは、Reactなどのコードを実際に書く、あるいは設計に落とし込む等の具体的なアクションにすること。

出力例:

- [ ] 概念〇〇について、現在のSaaSプロジェクトのコンポーネント設計でどう実装できるか、簡単なスニペットを記事本文に追記する。
- [ ] 〇〇のパターンを実際のサンドボックス環境で動かし、その結果（メリット/デメリット）をまとめる。
- [ ] 記事全体を「他人に説明するつもり（Teach to learn）」で見直し、 published: true に変更してマージする。
