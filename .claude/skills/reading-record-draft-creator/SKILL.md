# 読書記録 PR作成スキル (Reading Record Draft Creator)

ユーザーが提供する断片的なメモから「3Cプロトコル」の **Compress** フェーズを実行して読書記録のドラフトを作成し、週末の **Compile**（実践）セッションに向けたタスクリストを含む Pull Request を作成します。

## 3Cプロトコルとは

このスキルは以下の学習フレームワークに基づいています。

- **Compress（圧縮）**: 膨大な情報から「20%の核心」を選択・関連付け・チャンク化する。脳が一度に処理できるアイデアは約4つ。多くを記憶するより、強力な塊に圧縮することが重要。
- **Compile（実行・実践）**: 「90分の深い集中＋20分の休息」を1ブロックとして、学習→テスト→学習のサイクルを回す。「教えることで学ぶ（Teach to learn）」が最も効果的なテスト手段。
- **Consolidate（定着）**: 学習後の意図的な休息と睡眠により、脳が情報を定着させる。このスキルの直接の対象外だが、Compileタスクを実行した後に意識すること。

ドラフト作成（このスキルの役割）は Compress フェーズに相当します。

---

## Key Parameters / Rules (制約事項)

- 作業ディレクトリ: `content/entries/`
- ファイル形式: `.mdx`（既存エントリーに合わせる）
- ユーザーの執筆体験（Obsidianの利用）を阻害しないため、複雑な装飾は避け、シンプルなMarkdownで記述してください。
- 出力ファイルは必ず `published: false` を設定してください。

---

## Common Workflows (実行ステップ)

### Step 1: 情報の構造化 (Compress)

ユーザーから渡された入力データを分析し、以下の要素を抽出・補完してください。

- **書籍・ソース情報**: タイトル、著者、URL/Amazon URLなど（不明な場合は検索して補完）
- **学びの要点（20%の抽出）**: 最も重要な概念を1〜4つに絞り、チャンク化（短い要約・比喩・図の言語化）してまとめる。既存知識との接続（Association）があれば明示する。
- **読むきっかけ**: ユーザーのメモから動機・背景を推測する。

### Step 2: ファイルの生成

`content/entries/` 配下に `[英数字のslug].mdx` というファイル名で作成してください。

Frontmatterは以下の形式で付与してください。ソースが複数ある場合は `sources` 配列に追加します。

```yaml
---
title: "[メモから推測した記事タイトル]"
date: YYYY-MM-DD
published: false
sources:
  - book_title: "[書籍・記事のタイトル]"
    author: "[著者名]"
    # url: ""          # Web記事の場合
    # amazon_url: ""   # 書籍の場合（Amazonリンク）
    # cover: ""        # 書影URLがあれば
---
```

本文は以下の見出し構成としてください。

```md
## 読むきっかけ

（Step 1で推測した動機・背景を簡潔に記載）

## 学びの要点

（Step 1で構造化した内容を記載。箇条書きや太字を活用して読みやすく）

## 接続アイデア（任意）

（本の内容を自分の文脈に当てはめる仮説があれば記載。なければこのセクションは省略）
```

### Step 3: Git操作とPR作成

1. `main` ブランチから最新の状態を取得し、`draft/YYYYMMDD-[slug]` という新しいブランチを作成する。
2. 作成したファイルをコミットし、リモートにプッシュする。
3. `main` ブランチに対して Pull Request を作成する。

### Step 4: PR概要欄の作成 (Compileの準備)

Pull Request の Description (本文) には、ユーザーが週末に **90分1ブロック以内** で実行すべき「実践・検証タスク」をチェックリスト形式で必ず出力してください。

タスクは本の内容・ジャンルに沿った具体的なアクションにすること（技術書ならコードを書く、ビジネス書なら設計や文章に落とす、など）。

最後のタスクは必ず「Teach to learn」の検証として、記事を第三者に説明するつもりで見直し、`published: true` にしてマージする締めくくりにしてください。

出力例:

```
- [ ] 概念〇〇について、自分のプロジェクトへの適用イメージを記事本文の「接続アイデア」セクションに追記する。
- [ ] 〇〇のパターンを実際に手を動かして試し、気づき（メリット/デメリット）を箇条書きで本文に追記する。
- [ ] 記事全体を「他人に説明するつもり（Teach to learn）」で見直し、published: true に変更してマージする。
```
